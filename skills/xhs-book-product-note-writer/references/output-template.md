# 输出模板

默认输出一个 Markdown 文档。不输出图片、拍摄方案、发布排期、运营建议或大段创作说明。

# 首批xhs图书商品笔记初稿

## 1. 物料总览

| 序号 | 对应买点场景 | 主要用户处境 | 时间窗口 | 核心购买理由 |
|---|---|---|---|---|

总览必须覆盖报告中的全部首批建议测试场景，表格行数必须与后文笔记篇数一致。

## 2. 笔记初稿

对每个场景重复以下结构：

### 笔记 N：场景名称

#### 对应场景

用 1—2 句话说明本篇对应谁、在什么时刻、测试什么主买点。该段供编辑理解，不属于发布正文。

#### 标题备选

1. 用户处境型：完整标题
2. 冲突或反常识型：完整标题
3. 具体内容、方法或结果型：完整标题

不要保留“用户处境型”等标签的解释文字到标题本身。

#### 正文初稿

直接写完整正文。使用手机端短段落并保留空行，每篇包含 3—6 个承担导航作用的表情符号。不得插入写作说明、分镜、图片建议、占位符或小标题式提纲。

#### 写作依据

- **核心证据**：列出实际使用的 1—2 项报告证据。
- **页码/章节**：沿用报告或核验后的定位；不确定时明确待核。
- **核查备注**：只列页码、引文边界或少量定位问题；无则写“无”。无法确认真伪的内容不得已写入正文。
- **避免夸大**：写出本篇最主要的真实性边界。

## 3. 批次核对

- 报告首批场景数：N
- 输出笔记数：N
- 未覆盖场景：无 / 列明并解释阻断原因
- 重复主买点：无 / 列明
- 重复核心证据或工具：无 / 列明复用篇目及不同购买动机
- 需要优先核查的证据：列明或写“无”
- 优先级计数：重点__ + 组合__ + 候补__ = 总数__
- 手机端排版检查：通过 / 列明不合格篇目
- 表情符号检查：每篇 3—6 个 / 列明不合格篇目
- 时间时态检查：通过 / 列明不合格篇目

除非输入缺失到无法辨认场景，否则不得以篇幅或时间为由漏写首批场景。
