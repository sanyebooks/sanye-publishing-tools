# 图书选题七问评估

把“感觉这个选题好不好”转换成有证据、可追问、可复核的立项判断。不要让总分掩盖必须项硬伤。

## 开始前

1. 读取 `references/evaluation-framework.md`，使用七个维度、权重、锚点和致命短板规则。
2. 读取 `references/input-and-evidence.md`，建立事实卡并区分事实、推断与未知。
3. 需要生成 Excel 时，读取 `references/workbook-standard.md`，使用当前平台可用的电子表格能力制作和验证工作簿；若当前平台不能生成 `.xlsx`，先交付结构完整的 Markdown 评估报告，不得因此省略评分依据、致命短板和验证动作。
4. 涉及当下市场规模、竞品销量、渠道趋势或平台表现时，优先核验最新资料并保留来源；无法联网或无可靠来源时标为“待验证”，不要伪装成市场事实。

## 工作流程

### 1. 建立选题事实卡

先提取：书名/项目名、作者与可验证资源、品类、核心读者、核心问题、内容结构、产品形态、价格与装帧设想、竞品、渠道、公司资源和战略目标。

缺少的信息不等于低分。把它标成“未知”，再提出最能改变结论的追问。默认一次最多追问 7 个问题，优先补齐五个必须项。

### 2. 建立证据台账

每条证据注明来源位置，并归入以下等级：

- `A 直接证据`：书稿原文、用户研究、真实销售/投放数据、已确认合作或渠道数据。
- `B 间接证据`：可靠竞品、作者历史表现、行业报告、可复核案例。
- `C 合理推断`：由材料推导但尚未验证的判断。
- `D 未知`：没有足够材料。

没有 A/B 证据时，单项原则上不要评到 4–5 分。材料不足时输出暂定分和置信度，不要编造证据。

### 3. 评估五个必须项

逐项回答核心判断问题，给出：

- 原始分 `0–5`
- 加权得分
- 证据与来源
- 证据等级
- 判断理由
- 低分风险
- 下一步验证或改造动作
- 置信度 `高/中/低`

AI只对五个必须项进行 0–5 分评估。评分前不要先看希望得到的结论。

### 4. 请用户勾选两个加分项

两个加分项属于用户内部判断，AI不得根据材料代替用户选择。AI可以整理与“公司资源匹配度”“长期/战略价值”有关的已知资料，随后必须请用户分别勾选：

- `高`：折算 5 分，获得该项全部权重。
- `中`：折算 3 分，获得该项 60% 权重。
- `低`：折算 1 分，获得该项 20% 权重。

两项都完成选择前，只能输出“五项必须项初评”和待选择提示，不得输出最终总分、最终等级或正式评估报告。不得替用户默认选择“中”。

### 5. 应用致命短板与总分结论

严格按以下顺序判断：

1. 五个必须项未评完，或两个加分项尚未全部由用户选择：输出“待用户选择/待评分”。
2. 任一必须项低于 2 分：标记“存在致命短板（原硬门槛）”，输出“暂缓/重做选题”，即使总分很高也不得改判。
3. 无致命短板后，再按总分判断：
   - `>85`：重点加码
   - `70–85`：可以推进
   - `55–69`：小预算验证
   - `<55`：不建议重点投入

总分是讨论工具，不是自动立项器。结论必须同时说明最强证据、最大风险和哪些假设会改变判断。

### 5.1 写一句话结论

最终报告顶部必须提供一句能独立阅读的结论，不能只展示总分或等级。必须把最终决策放在句首，并用冒号与分析连接；即使用户不看分数，也能第一眼知道是否值得推进。用 1–2 句话同时写清：

- 最终决策等级：`重点加码/可以推进/小预算验证/不建议重点投入/暂缓或重做选题`；
- 这个选题最强的成立理由；
- 最关键的短板；
- 当前建议动作。

示例结构：`不建议重点投入：这个选题有____优势，但____仍不足；建议先____，再决定是否推进。`

不得把“建议不重点投入”“可以推进”等决策埋在句中或句尾。决策等级必须与总分及致命短板规则完全一致。

禁止使用“综合来看值得关注”“建议谨慎推进”这类没有说明原因的空话。未完成两个加分项选择时，不写最终一句话结论，只提示用户完成选择。

### 6. 给出下一步动作

动作必须对应薄弱维度，例如：访谈目标读者、测试一句话购买理由、制作样章/样书、比较三本竞品、验证纸书不可替代性、试投内容、确认作者资源或调整产品形态。不要只写“加强营销”“优化内容”。

优先列出 3 个验证动作，分别写明：要验证的假设、最低可行方法、通过标准和建议负责人/阶段（若信息允许）。

## 默认交付

先给一页式结论，再给七维明细：

1. 一句话结论与总分
2. 致命短板检查（任一必须项低于 2 分）
3. 七维得分表
4. 最强的 3 条证据
5. 最大的 3 个风险/未知
6. 建议的 3 个验证动作
7. 结论置信度与可能改变结论的条件

用户要求正式交付、开会材料或表格时，默认生成 `.xlsx`；仅咨询时可以先在对话中输出 Markdown 版。若用户尚未勾选两个加分项，先展示五项必须项初评并询问两个选择，收到选择后再生成最终版。

## 不得这样做

- 不得把材料缺失直接当作市场不存在；应区分“低分”和“未知”。
- 不得用两个加分项抵消必须项硬伤。
- 不得由 AI 代替用户勾选公司资源匹配度或长期/战略价值。
- 不得在两个加分项尚未都勾选时输出最终总分或最终评估报告。
- 不得只报总分而省略证据、风险和下一步动作。
- 不得把未完成、公式引用错误或空白状态显示为 0 分。
- 不得只显示“硬门槛触发/未触发”而不解释含义；用户界面使用“致命短板检查”，并说明是否存在低于 2 分的必须项。
- 不得凭书名、作者名气或个人偏好直接给高分。
- 不得编造销量、平台趋势、用户需求、作者资源或渠道承诺。
- 不得把“编辑觉得好”写成“读者愿意买”。
- 不得把电子内容也能完成的需求自动判为适合纸质书。
