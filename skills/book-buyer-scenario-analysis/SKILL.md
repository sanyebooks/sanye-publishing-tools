# 图书用户买点场景分析

把“这本书有什么卖点”转换为“什么样的人，在什么时刻，会因为什么具体理由想买这本书”。输出后续xhs商品笔记选题所需的策略底稿，不直接替代选题表或笔记成稿。

## 开始前

1. 完整读取 `references/analysis-framework.md`，按其中定义区分卖点、买点和用户买点场景。
2. 完整读取 `references/output-template.md`，使用其章节和字段交付。
3. 读取用户提供的全部书稿与封面。PDF、Word、图片等文件使用相应文档或图像读取能力；长书稿可分章处理，但最终必须跨章节综合。
4. 材料不完整时继续分析，同时标明证据等级、材料边界和待核项。只有封面而没有正文时，不得声称已深度理解文本。
5. 记录分析当天的日期与时区，建立从当天起未来 90 天的近期机会窗口。日期不明确时使用系统当前日期，不凭记忆假定当前月份。

## 工作流程

### 1. 建立图书事实卡

提取书名、作者、体裁/品类、核心议题、章节结构、内容机制、表达气质、可用页码体系和材料缺口。区分：

- `原文事实`：书稿直接支持；
- `封面信号`：由书名、副标题、腰封、视觉和装帧传达；
- `营销推断`：基于材料提出、尚未经过市场验证的判断。

### 2. 形成深度理解摘要

先回答以下问题，再寻找买点：

- 这本书真正试图解决、解释或呈现什么？
- 它通过什么独特机制完成，而不是只给出什么宽泛主题？
- 哪些观点、方法、人物、情节、案例或语言只有读过正文后才会发现？
- 它最可能改变读者的哪一种理解、感受、选择或行动？
- 它不能满足什么需求，哪些人不应作为首批测试对象？

不得把目录改写、作者光环或“治愈、成长、提升认知”等空泛词当作深度理解。

### 3. 建立原文证据池

从全书提取可支撑购买理由的具体证据：观点、方法、案例、数据、人物处境、情节后果、反常识结论、清单和关键表达。每条保留页码；无可靠页码时写 `待核页码：章节/位置线索`。

为证据标级：

- `A级`：正文明确支持，且有可靠页码或位置；
- `B级`：正文支持，但位置或适用边界仍需核对；
- `C级`：由封面、简介或局部材料推断，只能作为待测假设。

### 4. 从内容反推用户处境

不要先套年龄、性别、城市等级等泛人群标签。先识别用户正在经历的具体时刻：发生了什么、心里卡在哪里、尝试过什么、为什么现有办法不够、什么事件会让购买需求突然变强。

把宽泛人群改写成可观察的处境。例如，不写“职场女性”，而写“第一次带团队，却发现自己只会亲自救火的人”。

### 5. 生成候选买点场景

每个场景必须形成完整链条：

`具体处境 → 未满足需求/情绪 → 购买触发 → 本书独特回应 → 原文证据 → 可测试的点击入口`

一个场景只保留一个主购买动机。合并换词不换意的场景；同一原文证据可以服务不同场景，但必须说明用户动机为何不同。

### 6. 建立近期时间机会窗口

从分析当天向后检查 `0—14天`、`15—45天`、`46—90天` 三个窗口，识别与本书及用户处境直接相关的开学返校、考试、求职、毕业、节庆、假期、换季、年度规划、社会议题或生活节律。只保留能真实放大购买需求的节点，不为蹭节点强行关联。

对每个候选场景写清：

- 近期节点及明确日期范围；
- 为什么该节点会让需求变得更急、更具体或更易搜索；
- 最佳准备期、发布期和失效期；
- 该判断是 `日历事实`、`趋势假设` 还是 `已验证趋势`。

仅凭节令和常识推断时，使用“预计关注上升”“值得测试”等表述。只有获得平台数据、搜索指数或可靠来源后，才能写“搜索正在上升”或类似确定结论。

### 7. 评估首批测试价值

先按参考框架的五项内容标准各评 1—5 分，得到 `基础价值 /25`；再按近期窗口增加 `时机分 /5`，得到 `首测优先级 /30`。时机只能放大真实买点，不能挽救内容证据弱或用户关系模糊的场景。

首批测试组合默认保留 6—8 个场景，并兼顾：

- 强痛点与正向愿望；
- 日常高频与人生节点；
- 核心读者与有依据的扩展读者；
- 内容价值、情绪价值与身份表达；
- 不同的封面/标题点击机制。
- 至少一个近期强时机场景和一个常青对照场景。

不要仅按总分机械取前几名；场景高度同质时保留代表项并补入不同假设。

### 8. 分析封面与内容的配合

判断封面已经传达什么、遮蔽什么、可能吸引或劝退谁。封面只作为市场入口信号，不能替代书稿证据。提出后续xhs测试画面时，优先考虑真实阅读场景、人物痕迹、内容局部和使用结果，不默认只展示精修书封。

### 9. 输出策略底稿

严格使用 `references/output-template.md`。先给结论，再给证据和测试矩阵。写清哪些是高置信判断，哪些需要通过首批笔记验证。

图书事实卡、材料核查和封面判断只作为内部分析过程，不单列输出；仅将其中会改变买点判断的结论放入对应场景、证据或风险字段。用户明确要求时再单独展开。

## 质量门槛

交付前检查：

- 是否真正读过正文，而不是只复述书名、目录和封面文案；
- 每个优先场景是否包含具体时刻、购买动机、本书回应和证据；
- 是否把用户买点误写成出版社自说自话的产品卖点；
- 场景是否具体到能想象人物、地点、动作和心理，而不只是人口标签；
- 本书回应是否具有独特性，换成同品类任意一本书后是否仍然成立；
- 是否把营销推断标为假设，而非已验证的市场事实；
- 首批场景是否覆盖不同假设，而不是同一个痛点的多次改写；
- 是否写明分析日期、未来 90 天窗口和每个场景的时效等级；
- 是否把日历推断误写成已经验证的搜索趋势；
- 是否遗漏了近期节点对选题先后顺序的影响；
- 是否越界生成了大批标题或完整笔记。用户另有明确要求时再进入下一阶段。

## 不得这样做

- 不得编造书稿内容、数据、人物、作者经历、读者反馈或精确页码。
- 不得把“装帧精美、名家推荐、内容丰富”直接当作用户买点。
- 不得用“所有人、年轻人、女性、职场人”等大词代替具体处境。
- 不得只输出人群画像而缺少购买发生的时刻。
- 不得为了追求网感歪曲原意或许诺书稿无法兑现的效果。
- 不得把“可能适合”写成“市场已经证明”。
- 不得在本阶段批量生成笔记成稿；输出应能为下一阶段选题提供判断依据。
